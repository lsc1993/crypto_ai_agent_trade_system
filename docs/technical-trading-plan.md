# 技术研究交易计划书 v2

实现日期：2026-10-10。代码实现、测试、部署与真实模型质量分别验收。

## 使用与内容

技术报告区保留综合研究入口。手动生成提交后台任务，显示采集、思考分析、校验、编排和保存阶段。URL 的 runId 可用于刷新恢复；查询失败重试查询不会重新生成。完成后打开独立历史详情。

新 technical-v2 包含当前立场、支持与反证、入场确认、止损依据、目标依据、失效/取消、备选情景、等待、Skill 应用和风险。旧 technical-v1 保留原展示与同步接口，历史不可变。

没有符合规则的候选时输出具体等待条件，不虚构价格。仍使用[技术报告](technical-reports.md)的确定性突破候选规则：多周期方向一致、结构价格合理、成本后盈亏比达到阈值。回踩/逆势反转候选尚未实现；模型可以拒绝候选，但不能改写数值。

## 两阶段与引用

第一阶段接收本次冻结的完整指标、价格、候选和选定方法，开启思考，输出结构化分析摘要。第二阶段关闭思考，根据已验证摘要编排正文。原始 reasoning_content 不展示、保存或转发。

数字通过字段引用占位符由程序渲染为带标签/单位的十进制字符串，止损/目标/入场有字段角色校验。未知字段、外部证据、未选方法、未绑定数字、订单语言及收益承诺被拒绝。引用校验不能证明自然语言推断一定正确，仍需对照支持、反证和冻结日期复核。

价格章节必须在正文实际插入对应角色字段；占位符不允许追加冲突单位。候选状态、数据截止和有效期提示由程序生成，不允许立即执行措辞。详情先显示立场与等待，随后显示条件价格计划，审计置后。

允许“入场、止损、目标、条件做多/做空”等研究术语，不输出账户金额、仓位、杠杆或 TradeIntent。历史触发仅代表截止时的收盘确认，不持续监控，不是实时执行依据。

## 额度与失败

| 独立设置 | 默认值 |
| --- | --- |
| technical_analysis_max_tokens | 32768，含思考与输出 |
| technical_composition_max_tokens | 8192 |
| technical_analysis_timeout_seconds | 180，每次请求 |
| technical_composition_timeout_seconds | 90，每次请求 |
| technical_run_timeout_seconds | 600，整个任务 |

每阶段最多两次。分析初始 high；length 或空正文后第二次使用 low，思考仍启用。限流等待最多五秒，认证/参数错误不重试；任务为降级保存预留最后十五秒。保存失败不能宣称已交付。

两阶段成功为 completed；分析成功但编排失败保留摘要并规则编排；分析失败保存确定性规则结果；行情不足跳过模型。后三者标 degraded。外部模型每次成功无法保证。

generation.diagnostics 和 technical_plan_model_stage 日志仅含阶段、次数、finishReason、token 数、耗时、模型、思考等级及额度，不含正文、Prompt、思考或凭证。沿用现有模型/密钥配置，本次不修改 .env。

格式重试仅提示白名单字段路径和错误类别，不回传被拒正文。2026-10-10 修复：文本校验失败同时反馈静态规则码（数值、交易词、即时执行措辞、占位符单位等），未知校验消息归为 schema；`technical_plan_response_rejected` 安全日志记录同一摘要，不含原文或推理。提示明确字面禁词在否定句中也不可出现，周期和指标编号改用定性名称或引用占位符；校验边界保持。任务失败终态与已启动研究的审计终态在同事务提交；恢复已有报告优先于失败，重复审计写入保持幂等。

增量纠错：第一次输出局部失败时，程序逐条验证正文、当前证据、字段引用、方法引用和章节角色，重试输入只携带这些合法段落及其位置；拒绝的段落与推理不回传。重试补写失败位置，程序保留合法段落原文并对合成后的整篇再次执行相同校验。候选、等待理由或角色引用缺失的相关章节不锁定；超长整篇允许重新缩写。仍然每阶段最多两次，不增加额度、调用次数或执行权限；无法修正仍保存真实降级状态。

增量纠错验收：`backend/` Ruff、Pyright 和专用 PostgreSQL 下全量 pytest 656 项通过；部署后 BTCUSDT 报告 `dff6814c-2435-4ba6-8e6d-6775a0b39f24`、ETHUSDT 报告 `459e7490-dc9a-4158-830b-a745eb4b1188` 均 completed/complete、两阶段首轮通过，正文分别 4755/4085 字符，关联审计正常完成。另以不保存报告的受控故障注入模拟两段数值违规，真实模型纠错通过且合法段落不变。这证明增量纠错可用，不代表长期模型成功率保证；旧降级记录保留。

## API 与持久化任务

| 请求 | 行为 |
| --- | --- |
| POST /api/v1/technical-reports/runs，{symbol, requestId} | 202 创建/复用任务，requestId 是客户端 UUID |
| GET /api/v1/technical-reports/runs/{runId} | 查询阶段/终态；结果 reportId 或安全失败码 |
| POST /api/v1/technical-reports，{symbol} | 保留 v1 同步生成，201 |
| GET /api/v1/technical-reports/{id}、分页列表 | v1/v2 不可变历史 |

同请求键幂等、同键不同币种拒绝、同币种活跃任务复用。容量二十，全局并发一，通过数据库协调行与租约跨实例控制。入队/执行均核验研究目录，归档只允许历史读取。

API lifespan 的专用固定 worker 执行手动任务。状态 queued/running/completed/degraded/failed，租约三十秒、心跳十秒。过期运行恢复已有报告或标 interrupted，不自动重放付费调用。保存事务锁定任务并校验服务器时间租约；报告与 Harness 终态同事务提交。报告已提交、任务更新中断时按 analysisId 恢复，不重复生成。

关闭服务停止领取，等待最多五秒后取消并释放资源。不扩展 Harness 工具权限，不增加自动监控、定时报告或交易执行。

## 升级与验证边界

迁移 0018_technical_report_runs（父版本 0017）新增任务、请求键及协调表；v2 仍使用现有 JSONB 报告列，不改写旧报告。后端、前端、迁移应一起部署，按既有流程先备份，再迁移并检查健康、生成及历史读取。本次开发不自动推送、业务迁移或部署。

pytest 固定样本/HTTP 替身、专用 PostgreSQL、Vitest 与 Mock Playwright 分别验证模型流程、队列/审计、契约和界面。真实模型质量、行情现场连通、延迟成本基准与交易效果未由替身测试证明。

独立审查发现的中文数值、引用角色、历史信号措辞、取消顺序、重试预算和崩溃审计问题均已补回归并修正。剩余预算不足一次请求时不重试；关闭先取消模型工作，再限时写入失败状态和收集子任务；不可用时由过期租约恢复，已启动的 Harness 轨迹幂等补中断终态。

开发验收：`backend/` Ruff、Pyright、全量 pytest 647 项通过（独立 PostgreSQL）；`frontend/` lint、typecheck、Vitest 262 项和 build 通过；Mock Playwright 6 项通过，包含生成、历史读取和刷新恢复。构建保留已有大包体积提示。首次全量测试的 Windows 临时目录权限错误已改用独立目录重跑通过。

2026-10-10 降级修复验收：后端 Ruff、Pyright 和全量 pytest 651 项通过（专用测试数据库）。修复已部署，真实 BTCUSDT v2 报告 `41670ebb-0ef8-4bb6-a5cc-7ed99bef6cf8` 状态 completed、质量 complete、错误码为空，正文十一节共 3518 字符。分析阶段保持 high 思考，格式纠正后通过；编排阶段关闭思考且首次通过，关联 Harness 终态为 workflow_completed。该样本验证生成、纠错、保存及展示，不证明模型长期稳定性或交易表现。无 schema 变更，迁移仍为 0018；旧降级记录不回写。
