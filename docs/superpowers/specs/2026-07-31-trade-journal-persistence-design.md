# 手工交易日志与复盘持久化设计

**日期：** 2026-07-31
**状态：** 已确认，待实施计划

## 目标

将工作台现有的手工交易日志与复盘统计从浏览器 Mock 数据迁移到 PostgreSQL，同时保持系统为无账户、无下单、无交易所私有 API 的研究工具。用户录入、编辑、作废或归档交易后，系统必须以可追溯的原始成交腿、资金现金流和追加式审计事件为依据重算已实现盈亏与统计。

本期仅支持 `BTCUSDT`、`ETHUSDT` 的 `long` / `short` 手工交易。它不实现账户连接、订单同步、余额/仓位查询、自动执行、资金划转或提现。

## 已确认的领域语义

- 一笔交易代表同一标的、同一方向的一次手工持仓生命周期；交易可包含多条开仓、减仓与平仓成交腿。
- 所有价格、数量、手续费、资金现金流与盈亏在 Python 使用 `Decimal`，数据库使用 `NUMERIC(38,18)`，HTTP 与前端使用十进制字符串；禁止以 `float` 作为领域或持久化边界输入。
- 成交腿按 `(executed_at, sequence, id)` 稳定排序，并由 FIFO 计算器匹配开仓与减仓/平仓数量。减仓数量不得超过已开仓且尚未匹配的数量。
- 多单已实现毛利为 `(exit_price - entry_price) × matched_quantity`；空单为 `(entry_price - exit_price) × matched_quantity`。`net_pnl = gross_realized_pnl - total_fees + total_funding_cashflow`。
- 手续费始终为非负；资金现金流是有符号值，收取为正、支付为负。前端将把现有单一非负“资金费”字段替换为可增加的有符号资金现金流条目，保留发生时间与说明。
- 杠杆仅用于保证金和展示，不会放大实际盈亏。
- 编辑、作废与归档不物理删除交易、成交腿或审计数据。每次命令在同一事务内更新交易派生字段并追加不可变审计事件。
- 统计仅纳入完整平仓、未归档的交易；首期不计算未实现盈亏。胜率排除持平交易；没有亏损样本时利润因子为 `null`，前端显示为“不适用”，不伪造无穷或零值。

## 持久化边界

新增 Alembic `0004_create_trade_journal.py`，不修改既有市场和报告迁移。

| 表 | 职责 |
| --- | --- |
| `trades` | 交易身份、标的、方向、周期、可选报告关联、计划/复盘文本、状态、派生盈亏、打开/关闭/归档时间与审计时间。 |
| `trade_legs` | 成交腿的类型、UTC 执行时间、同刻顺序、价格、数量、手续费、作废状态与说明。 |
| `trade_cashflows` | 有符号资金现金流的 UTC 发生时间、金额、说明与作废状态。 |
| `tags` / `trade_tags` | 手工标签及交易关联，支持当前按标签查询。 |
| `trade_audit_events` | 追加式操作记录、关联 ID、操作类型、UTC 时间、变更前后快照与非敏感元数据。 |

`trades.analysis_report_id` 是对现有 `analysis_reports.id` 的可空外键，只保存不可变报告 ID，不复制报告正文、证据或提示词。所有数值与枚举均由数据库约束再次校验；`(trade_id, executed_at, sequence)` 对活动成交腿唯一。仓储只返回领域 DTO，不向服务层暴露 ORM 模型。

## 后端架构与 HTTP 契约

```text
FastAPI 路由 / Pydantic 请求响应
        ↓
TradeService / PerformanceAnalyticsService
        ↓
TradeCalculator（纯 Decimal FIFO）
        ↓
TradeRepository（单一 PostgreSQL 事务）
        ↓
交易、成交腿、资金现金流、标签、审计事件
```

`TradeService` 负责创建交易、完整更新手工草稿、作废成交腿/资金现金流、归档交易以及重新计算派生字段。每个写操作都会锁定目标交易，读取未作废原始事实，运行纯计算器，更新交易摘要并插入一条审计事件；任一校验失败时事务整体回滚。

新增版本化端点：

- `GET /api/v1/trades`：分页读取，支持标的、方向、周期、状态、标签和 UTC 时间范围筛选。
- `POST /api/v1/trades`：创建完整手工交易草稿。
- `PUT /api/v1/trades/{trade_id}`：以完整草稿更新交易，同时追加审计事件。
- `POST /api/v1/trades/{trade_id}/archive`：归档但不删除。
- `GET /api/v1/analytics`：按相同筛选条件从已完成、未归档交易即时聚合净盈亏、胜率、利润因子、期望值、最大回撤、权益曲线和交易日历。

数据库或服务不可用时，端点返回既有安全错误结构，不回退为 Mock 数据，不输出连接串、原始异常、凭证或用户输入全文。当前一次性公开市场采集命令保持不变；本设计不引入常驻采集任务。

## 前端衔接

`WorkbenchApi` 继续是页面唯一的数据访问边界。前端调整为：

- `mock` 模式保持现有可重置 Mock 行为和离线演示能力。
- `market-api` 的 Hybrid 实现继续读取真实市场和报告，并在本期完成后将交易列表、创建/更新和统计直接委托给本地 HTTP API；绝不以 Mock 掩盖真实接口故障。
- `api` 模式保持全部业务调用走 HTTP。
- 交易表单将资金费用改为有符号、可重复的现金流输入；其余现有字段和报告关联能力得到保留。
- 分析页面接收可空利润因子并明确展示“不适用”。

用户数据流为：表单 Zod 校验 → 本地 HTTP 请求 → Pydantic 校验 → 交易服务 → FIFO 重算与审计事务 → 十进制字符串响应。统计数据直接读取完整平仓的持久化交易；不缓存或持久化统计快照。

## 非目标

- 交易所账户、私有 REST/WebSocket、API Key、Secret、Passphrase、真实下单、撤单、仓位、余额、资金划转和提现。
- 自动或后台定时采集、任务队列、回测、策略执行、风险引擎或模拟盘。
- 未实现标记价格前的未实现盈亏，以及任何自动交易建议或收益承诺。
