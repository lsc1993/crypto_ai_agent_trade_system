# 多币对研究与币对管理设计草案

日期：2026-09-07。状态：待用户审阅；本文件仅为设计，尚未实现功能或执行数据库迁移。

## 1. 目标与已确认约定

研究工作台、市场详情、分析报告使用相同的币对下拉组件。选择币对后，行情、新闻、报告列表和生成报告操作均使用该币对。新增“币对管理”菜单，支持新增、移除、查看能力检查与数据同步结果、手动重试同步。

用户已确认：行情、K 线和衍生品等核心研究数据可用时，允许添加当前 ETF 适配器未覆盖的币对；ETF 专题必须显示“当前数据源不支持”。这不代表该资产没有 ETF，也不得借用 BTC/ETH 数据。

建议采用以下默认交互：三个研究页面共享并记住当前币对；移除表示停用研究配置，保留历史行情、报告和审计记录。首次添加自动同步，之后支持手动同步，并保持生成报告时按需抓取的新鲜度语义。

## 2. 现状与方案选择

代码检查发现：

- 后端 `market/contracts.py` 的 `ContractSymbol`、`market/capture.py` 的采集白名单固定为 BTC/ETH。
- 前端公共类型、HTTP 请求校验、市场导航和下拉候选尚未支持动态币对。
- 工作台接口同时获取 BTC/ETH 摘要及未按币对过滤的最近报告；真实 API 的新闻字段当前为空。
- 分析报告列表已有后端 symbol 筛选能力，但页面没有使用，生成按钮固定为 BTCUSDT。
- 新闻关键词及通用政策的关联范围固定为 BTC/ETH；ETF URL 映射也只有 BTC/ETH。
- 行情、报告、研究运行和 Harness 审计表存在 BTC/ETH 数据库 CHECK 约束；Harness 放行列表也固定为两种币对。
- 部分领域校验用 `is` 比较枚举币对；换为动态值后必须改为值相等，覆盖数据库与 JSON 反序列化场景。
- 回测和模拟盘另外限定 BTC，交易日志另外限定 BTC/ETH。

备选方案：

| 方案 | 收益 | 局限 |
| --- | --- | --- |
| 扩充固定枚举 | 初次改动较小 | 用户每次添加新币对仍需修改、发布代码，不满足管理页面目标 |
| 数据库研究币对目录 + 现有适配器能力检查（推荐） | 用户能自行管理；状态可持久化；复用研究链路 | 需要前后端类型调整、前向迁移及同步任务管理 |
| 通用多交易所资产平台 | 可覆盖更多市场 | 引入本次未要求的交易所、市场类型及额外维护成本 |

选择第二种方案。本期支持范围限定为现有 Binance USDⓈ-M 适配器可处理的、状态为 TRADING 的 USDT 保证金永续合约。是否支持某个具体币对以添加时实际检查为准，不预先声称 SOL、DOGE 等当前一定可用。

## 3. 页面与选择行为

### 3.1 共用研究币对选择

- 后端目录为唯一权威来源；前端不再维护研究币对枚举。
- 工作台和报告列表以 URL 查询参数 `symbol` 表示当前范围；市场页保留 `/market/:symbol` 深链接。
- 有效 URL 选择优先，其次为最近一次有效选择，再其次为 BTCUSDT（仍启用时），最后为目录首个启用币对。目录初始化完成之前不发出隐含 BTC 请求。
- 本地只记住选择值，不用本地存储决定某币对是否受支持。
- 三个页面顶部均显示可访问的下拉框；加载失败、数据为空、同步未完成时仍保留选择器和“币对管理”入口。
- 导航中的市场入口显示当前币对，例如 `ETHUSDT 市场`；无启用币对时显示“市场”。
- 查询缓存键包含币对。切换时不把旧币对数据作为新币对的占位数据；晚到响应不能覆盖当前页面。
- 显式无效或已移除的 URL 显示原因与可选币对，不能静默显示另一币对的数据。
- 移除当前选择后清理该值，按上述顺序选取其余币对。允许移除最后一个币对，三页进入可恢复的空状态。

### 3.2 研究工作台与市场详情

工作台只显示当前币对的市场摘要、已同步的相关资讯和最近五份报告。市场图表、衍生品、资讯及生成报告操作随选择同步切换。旧 BTC/ETH 切换链接替换为下拉框。

新闻按币对关联查询；通用宏观政策保留“市场公共背景”标识，不伪装成某币独有资讯。尚未同步新闻时显示空状态和同步入口。

### 3.3 分析报告

- 历史列表在后端先按币对过滤再分页，切换时页码回到第一页。
- 生成报告使用当前币对；切换时重置界面上的生成状态和订阅。已经提交的后端任务仍按提交时币对完成，但不得使新币对页面跳转到旧任务。
- 报告详情以报告本身的 symbol 为准，历史内容保持不可变。详情页切换币对时进入目标币对的报告列表，不重新标注已有报告。
- 移除币对后，已有报告仍可按 ID 查看；报告列表可通过“已移除币对的历史报告”只读入口查询。此范围没有生成或重试按钮。
- 新研究币对不自动扩展交易日志、回测或模拟盘能力；报告中相关后续操作按目标功能自己的能力显示。

## 4. 新增币对与能力校验

管理页提供币对输入（例如 `SOLUSDT`），可选的新闻名称关键词，以及“检查并添加”操作。输入去除首尾空白并转大写，要求 5–32 个 ASCII 大写字母/数字、以 USDT 结尾。新闻关键词是有限长度的纯文本，不接受 URL、正则表达式或工具配置。

后端依次检查：

1. 输入格式、是否已启用、是否已有待执行的同币对操作。
2. 项目已配置的适配器支持所需公开接口和持久化能力。
3. 通过适配器读取公开 `exchangeInfo`，核对 symbol、baseAsset、quoteAsset、marginAsset、contractType、status；只接受 USDT/USDT、PERPETUAL、TRADING。
4. 有界探测该币对摘要、四个周期已收盘 K 线、币对衍生品指标及资金费率历史，验证结构、数值、时间和返回币对一致性。
5. 生成逐项能力结果，区分“支持”“当前适配器不支持”“暂时不可验证”。ETF 使用明确的适配器覆盖信息，不从交易所合约存在性推断。

Binance 官方 [Exchange Information 文档](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Exchange-Information) 提供这些合约元数据。能力检查仍经项目的公开只读适配器，不接入新交易所或私有 API。

格式不支持、合约不存在、类型不支持、非交易状态等返回具体拒绝原因，不创建有效目录项或同步任务。超时、限流、连接失败返回“暂时无法验证，请重试”，不能误报成永久不支持。前端通过检查不能替代新增接口内的后端检查。

历史长度不足与接口不支持分别处理：至少每个周期有一根有效已收盘 K 线才可建立初始快照；少于 SMA50 所需的 50 根时允许添加并标记技术分析部分覆盖，沿用 UNKNOWN 结果。新上市币对的资金费率样本不足七天时同样展示部分覆盖。

检查通过后，事务内创建或重新启用目录项并登记同步任务，返回任务 ID。重复提交返回已存在的状态或进行中的同一任务，不能创建重复目录项。

## 5. 同步范围与数据语义

“与 BTC 相同的数据”指复用现有 BTC 研究采集范围及适用因子，不意味着其他资产应拥有同样多的历史样本或 ETF 来源。

| 数据 | 首次同步范围 | 缺失时的行为 |
| --- | --- | --- |
| 行情摘要 | 最新价格、24 小时涨跌及成交量、当前资金费率、未平仓量 | 核心失败，不能显示已就绪 |
| K 线 | 15m、1h、4h、1d；每周期与现有请求一致，最多 200 根，过滤未收盘数据 | 周期为空则失败；样本不足则部分覆盖 |
| 币对衍生品上下文 | 基差、多空账户比、主动买卖比，沿用现有观测粒度 | 本次核心同步失败，可重试 |
| 资金费率历史 | 最近 7 天已结算样本及现有统计 | 新上市历史不足为部分覆盖；读取故障为失败并可重试 |
| 英文新闻与政策 | 现有 8 个受治理 RSS；最近 7 天；币对新闻与相关宏观政策 | 单源失败隔离；没有相关文章不等于能力不支持 |
| 恐惧贪婪指数 | 现有 8 条历史读数及 7 日变化 | 标记来源失败或缺失；保留其市场背景含义，不称作该币专属指数 |
| ETF | 已有 BTC/ETH 适配器的披露日、基金贡献和五个完整披露日统计 | 不支持则显示“当前数据源不支持”；已支持但请求失败显示采集失败 |

为避免丢失可用数据，拆分币对衍生品与公共情绪的采集结果，再按已有报告契约组合；一个公共情绪来源故障不能丢弃已获取的币对衍生品事实。

同步复用采集器，不调用语言模型，不创建虚假的分析报告。行情与 K 线保存至现有市场表和不可变输入表；新闻保存至现有新闻表；附加指标、资金费率、ETF 的规范化载荷及哈希保存至本次同步记录。所有来源保留观测时间、抓取时间、覆盖状态与安全错误码。

已有快照不得冒充本次同步成功结果。失败时可以继续查看上次成功数据，但必须同时标示其时间及本次失败。生成报告仍以本次请求重新采集和冻结的证据为准。

本期新增自动首次同步和手动同步/重试；保持 BTC 现有的按需报告采集方式，不新增全天定时抓取所有币对的任务。现有批量采集脚本改为读取启用目录，并对币对逐个记录结果，单个币对失败不拖垮其他币对。

## 6. 后端边界与存储

### 6.1 币对类型与研究准入

新增经过格式验证的 `ResearchSymbol` 值类型，用于行情、新闻、研究报告和研究 Harness。研究入口另通过目录校验启用与同步状态，不能仅凭字符串格式放行。历史读取只验证标识格式，不要求目前仍启用。

保留交易相关的 `ContractSymbol` 与既有显式限制。共用 Candle 等市场模型使用研究标识后，消费端按值比较；不能通过扩大公共枚举间接放开 TradeIntent、风控、模拟盘或回测的范围。

Harness 的研究币对白名单从后端目录构造，运行时冻结目录版本和当前币对的获准能力写入审计。不得由浏览器提供白名单，也不得由模型决定是否放行。保留现有公开读取、受治理新闻、受限模型和不可变报告能力约束。

### 6.2 新增表与迁移影响

需要一条基于当前迁移 head 的前向 Alembic 迁移，实施时先确认没有并行迁移冲突：

- `research_symbols`：symbol 主键、基础/计价/保证金资产、合约类型、启用状态、新闻关键词、能力快照、版本、创建/停用时间。
- `research_symbol_sync_runs`：任务 ID、symbol、目录版本、排队/运行/就绪/部分覆盖/失败/取消状态、阶段、租约令牌和截止时间、开始/结束时间、市场快照 ID、逐来源载荷与哈希、安全错误摘要。终态结果保持不可变，重试创建新运行。
- `research_symbol_events`：追加记录检查结果、添加、移除、重新启用、同步阶段及终态，关联操作/任务 ID。
- `research_news_links`：关联既有新闻 ID 与研究币对及关联范围。新闻本体按原去重规则保存；新增币对关联独立追加，避免复用旧新闻时只能得到最先匹配的 BTC/ETH 标签。

对 `market_candles`、`derivative_observations`、`market_snapshots`、`market_snapshot_inputs`、`analysis_reports`、`analysis_evidences`、`agent_analysis_runs`、`harness_runs` 的币对列统一扩至 32 字符。已有两币 CHECK 约束在存在时替换为标识格式约束，并通过目录外键保持可关联性。先登记 BTC/ETH，再建立外键。

BTC/ETH 默认启用；复用其已有历史记录，并登记初始化同步任务补齐管理状态。迁移本身只改数据库，不访问外部数据源。交易日志、回测和模拟盘的币对约束保持原样。

使用现有 PostgreSQL、SQLAlchemy、HTTPX 与 asyncio，不新增生产依赖。迁移保留全部既有审计内容，不更新历史载荷与哈希，也不提供删除历史数据的回退迁移。新旧后端与前端须作为配套版本发布。

### 6.3 同步任务可靠性

后端 lifespan 中启动消费器，读取数据库中的用户触发任务。每实例最多同时同步两个币对，数据库使用原子领取与租约防止重复工作；同币对最多一个待处理或运行任务。

单来源超时沿用现有上限，总运行设置 120 秒上限；租约 30 秒、每 10 秒续租。租约失效的运行标记为可重试失败，旧工作者不得写入终态或启用状态。服务重启可以继续领取尚未开始的任务，运行中断则显示可重试失败，不永远停在“同步中”。

就绪表示核心采集完整且适用的附加来源完整；核心完整但可选来源缺失为部分覆盖，仍可研究。已明确不适用的 ETF 能力单独展示，不当成网络故障。核心失败阻止新币对首次进入可生成状态。

同步中的币对出现在下拉列表中并显示状态，初次同步完成前禁用生成按钮。已有就绪币对刷新失败时仍允许用户发起独立的按需研究，报告沿用自身的失败和降级语义。

移除时增加目录版本，取消待执行任务并阻止后续任务；运行中采集通过协作取消及版本检查防止重新启用该币对。已完成的来源与审计保留。移除前已准入的报告可按冻结输入完成并作为历史查看。

### 6.4 建议接口

所有契约使用 Pydantic，前端使用对应 Zod 校验。路径位于 `/api/v1`。

| 接口 | 作用 |
| --- | --- |
| `GET /research-symbols` | 返回目录、能力及最近同步状态；可显式包含停用项 |
| `POST /research-symbols/check` | 有界能力预检，返回逐项结论，不登记有效币对 |
| `POST /research-symbols` | 后端检查并创建/重新启用目录项，登记首次同步，返回 202 和任务 ID |
| `POST /research-symbols/{symbol}/archive` | 幂等停用并记录事件，界面显示“移除” |
| `POST /research-symbols/{symbol}/sync` | 手动同步或重试；进行中则返回当前任务 |
| `GET /research-symbol-sync-runs/{id}` | 查询持久化进度与逐来源结果 |
| `GET /dashboard?symbol=...` | 返回选定币对的摘要、新闻与最近报告 |

现有市场和报告入口校验动态研究标识，并按目录执行研究准入；批量 markets 请求上限从固定两个改为有界的 50 个。报告按 ID 的历史查询不受停用影响。保留旧 dashboard 无参数调用的默认行为以降低兼容影响，三个新页面始终显式传 symbol。

错误信息区分不支持、重复、停用、未就绪、存储不可用和暂时无法校验。管理页展示每个来源的原因与可执行的重试动作，不暴露上游响应正文或凭证信息。

## 7. 前端数据模式与新闻兼容

同步更新 WorkbenchApi、HTTP、Hybrid、Mock 三种实现及所有研究响应校验。API/Hybrid 的目录和能力必须来自后端；Mock 使用确定性的离线能力与同步结果，并明确为示例，不能声称外部验证成功。

研究标识与交易标识在前端分开。删除默认 BTC/ETH 枚举时，仅替换研究通路；交易表单保留其支持范围。市场图表标签和数值格式检查低价币显示，避免全部价格显示为 0.00。

新闻新增请求范围的匹配器：保留 BTC/ETH 名称别名；新币默认匹配规范 ticker，附加可选名称关键词。宏观来源使用原确定性规则关联当前研究范围。匹配结果写到追加关联表，历史报告的冻结新闻快照不变。没有匹配文章明确为空，不借用其他币对文章。

## 8. 验收与验证

实现前先写 pytest 和前端交互测试，再实现对应行为。验证至少覆盖：

1. BTC/ETH 下拉切换，以及第三种测试币对添加后，三个页面请求、数据、列表筛选和生成操作一致。
2. 快速切换、请求乱序、刷新、直接 URL、浏览器后退、生成中切换，均不发生跨币对数据或跳转串用。
3. 当前适配器不支持的 ETF 显示准确原因，且模型不得为其生成无证据的 ETF 判断。
4. 不存在、停牌、非 USDT 永续、格式错误、超时及限流得到不同的可理解结果；绕过前端直接请求仍受校验。
5. 初始同步覆盖上述数据清单；四周期空数据、短历史、单 RSS 故障、公共情绪失败等状态正确。
6. 重复新增、并发同步、任务重启、中途移除、移除后重新添加及最后一个币对移除可恢复。
7. 新闻去重后追加新币对关联不会丢失匹配结果，历史新闻和报告证据哈希不变。
8. 前向迁移可在隔离测试 schema 上运行；新币对可完整保存行情、报告及 Harness 审计，既有 BTC/ETH 报告可读。
9. 新币对不会被模拟盘、回测或 TradeIntent 意外接受；公共适配器请求仍限制在现有获准主机和公开读取端点。
10. UTC、Decimal、快照哈希、未收盘 K 线过滤和采集截止时间回归，确保无未来数据泄漏。
