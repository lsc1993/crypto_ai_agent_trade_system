# 可复现质量验证设计

## 目标与范围

落实项目审视中优先建议的统一验证入口与 CI、环境及测试库预检、固定离线模型评估集。用户已要求按建议执行；本文记录具体工程选择，便于审阅，不改变研究和交易边界。

## 方案选择

采用 Python 3.12 标准库实现根目录 `scripts/verify.py`，复用 uv、npm 和现有测试命令。相比仅支持 PowerShell/Bash 的脚本，跨平台入口更容易在 Windows 本地与 Linux CI 保持一致；相比引入任务框架，无新增生产或开发依赖。提供 doctor、quick、full、eval、e2e 检查档位，分开报告失败和缺少前置条件；任一失败或阻塞均非零退出。快速检查不代表完整验收。

数据库防护使用共享测试支撑模块，读取显式测试环境配置、拒绝业务库同目标及非测试命名，并在连接后只读核对数据库身份与角色权限。检查在建 schema/迁移之前执行，连接串与原始异常不输出。CI 使用独立临时 PostgreSQL 与受限测试角色；不更改业务配置、历史迁移或业务库。数据库名字只是辅助检查，不构成独立安全保证。

模型评估放在开发脚本和测试样本中，版本化记录样本、Prompt/契约标识，调用现有确定性校验和模型适配器的离线响应路径。包括合法输出、无效格式、伪造证据、交易措辞、注入文本和证据不足等场景。汇总以预期行为匹配为准，合法率、预期拒绝和降级分别报告，不能把拒绝都算模型质量成功。无网络或真实模型调用，不形成收益或真实研究质量承诺。

## 验证与边界

新增逻辑先写失败测试，再实现；检查聚合器要验证非零退出、缺失工具、超时、敏感输出抑制和空检查集。数据库拒绝必须发生在写入前，所有使用独立迁移连接的测试也受防护。评估器必须有故意错误预期导致非零退出的检查。

CI 采用 GitHub Actions，最小只读仓库权限，不使用仓库密钥，不发布或部署。完整档位检查格式、lint、类型、pytest、Vitest 和构建；Playwright 单独声明为 Mock 界面验收，不代表 HTTP 集成验收。现有格式存量以一次独立机械格式整理处理，保持历史迁移可执行语义不变。

本轮不扩展 AST 架构门禁、HTTP 端到端流程、自动交易、通用工具路由或付费模型评测。后续项目仍按状态索引跟踪。
