# 交互式加密货币研究 AI Agent 升级需求

- 版本：1.0
- 日期：2026-11-06
- 文档类型：需求汇总与后续设计输入。
- 状态：核心目标、交互方式和默认审核规则已在需求讨论中对齐；本文汇总这些结论，具体架构、接口和实施计划尚待设计。
- 实现状态：目标需求，尚未实施；不得用本文替代当前运行说明或功能验收记录。
- 适用范围：现有本地研究工作台的增量升级。

## 1. 背景与需求来源

用户希望把以新闻、行情分析和报告生成为主的研究系统，升级为能够自主推进研究、使用工具与知识、解释分析过程，并与用户协作完成决策评估和交易计划的完整 AI Agent 系统。

需求输入包括用户提供的《加密货币交易研究系统 AI Agent 架构升级与开发实施方案》V1.0（2026-11-05），以及随后对完整 Agent 能力、任务中交互、审核规则和可选监控的补充。该技术方案提供架构参考；本文以本轮已对齐的产品目标及当前仓库事实为准，不照搬其中的目录、技术依赖、工期假设或能力状态。

本文区分三种内容：

1. **已对齐需求**：用户明确提出的目标，以及用户选择保留的默认审核规则。
2. **设计建议**：为使需求可实施而提出的默认方案，明确标注为建议，不冒充用户逐项确认的决定。
3. **后续设计事项**：预算阈值、模型适配、检索实现等技术细节，不阻塞需求成文，不代表已经选定或启用。

## 2. 当前系统基线

以下为文档与静态代码核对结果，不代表本轮重新完成部署、数据库或真实模型验收。变化中的现状仍以[项目状态](../../project-status.md)为入口。

| 领域 | 当前已有基础 | 与目标的主要差距 |
| --- | --- | --- |
| 综合研究 | 固定 LangGraph、公开行情与新闻、专题、冻结证据、引用与数值校验 | 模型不能动态选择工具和研究步骤 |
| 技术研究 | 技术 v2 两阶段模型、确定性条件候选、后台任务与历史报告 | 方法由程序选择，缺少用户可选策略池和运行中人工交互 |
| Harness | 研究准入、能力约束、固定生命周期与审计 | 缺少面向动态工具循环、等待输入及恢复的完整治理 |
| 持久化 | PostgreSQL、不可变报告与审计、图 checkpoint、技术任务租约 | 图 checkpoint 不等于所有中间证据和运行上下文均可完整恢复 |
| 回测与模拟盘 | 确定性回测、风控与手动模拟盘 | 范围有限，不能自动扩展为任意研究币种和策略的交易能力 |
| 质量 | 静态检查、固定评估、服务流程与持久化测试 | 真实模型语义质量仍需独立评估，格式和引用通过不足以证明结论正确 |

当前技术任务请求只有币种和请求标识，队列会合并同币种活跃任务；策略选择接入后必须相应调整。当前技术候选选择引用也有固定单候选限制，需要在设计中处理。

基线依据：[AI 维护指南](../../ai-maintenance.md)、[运行边界](../../operational-boundaries.md)、[技术交易计划书](../../technical-trading-plan.md)、[技术研究接口](../../../backend/src/app/api/routes/technical_reports.py)、[任务仓储](../../../backend/src/app/infrastructure/persistence/technical_run_repository.py)、[技术计划契约](../../../backend/src/app/reports/technical_plan.py)。

## 3. 已对齐的目标与范围

### 3.1 五项业务目标

| 标识 | 目标 | 预期结果 |
| --- | --- | --- |
| G1 | 提供更全面、专业的分析报告 | 市场事实、技术结构、事件、支持与反证、情景和限制有组织且可追溯 |
| G2 | 支持 AI Agent 市场分析 | 模型能够规划、调用工具、检索知识、处理反馈并调整后续研究 |
| G3 | 借助 LLM 辅助交易决策 | 解释策略适用性、比较情景、选择或否决候选，允许等待和放弃 |
| G4 | 借助 AI 制定交易计划 | 输出与所选策略绑定、条件明确、可审核和可追溯的计划草案 |
| G5 | 支持策略池 | 用户提供不同策略，并在本次研究或计划中选择使用；具体策略算法后续讨论 |

### 3.2 完整 Agent 的核心能力

以下均纳入核心目标，不能仅提供接口占位或继续只把模型用作报告格式化器：

- 模型驱动的有限研究循环与 Tool Calling。
- 经治理的 MCP 工具接入。
- 知识检索 RAG。
- 动态上下文组织与会话内交互。
- Token、调用次数、时间和成本预算控制。
- Agent Harness、运行持久化、中断与恢复、审计及评测。
- 可观察的分析摘要、工具轨迹和决策依据。
- 用户澄清、审核、修改、拒绝、取消及继续任务。

持续监控纳入可选能力目录，默认关闭，不是每个研究任务的默认行为。其发布批次由实施设计安排；未实现时应明确不可用，不能用演示开关冒充可用能力。

### 3.3 本轮范围边界

- 以现有本地工作台为基础增量升级，保留现有历史报告与既有功能。
- 新 Agent 的结果是研究报告、决策评估和条件交易计划；计划采纳不会产生订单。
- 本轮不要求实现 MACD、三重过滤等具体算法，也不要求新增真实交易能力。
- 研究准入范围不自动扩大回测、模拟盘或交易契约的币种和方向范围。
- 研究计划继续保持账户与执行隔离；本轮不新增真实账户读取、资金金额、仓位或杠杆计算输出。若后续需要账户相关规划，应另行定义确定性计算与授权边界。
- 自动策略组合、任意代码执行、自主安装工具、自动扩大权限、多用户 SaaS 和多交易所扩展不属于本轮已确认交付。

## 4. 三类业务结果

| 结果 | 回答的问题 | 必须呈现的信息 |
| --- | --- | --- |
| 市场研究报告 | 市场当前处于什么状态？ | 数据范围、市场结构、驱动因素、周期冲突、支持与反证、情景、来源和限制 |
| 决策评估 | 所选策略是否适用于当前条件？ | 策略适用性、满足与未满足条件、候选取舍、反证、等待或放弃理由 |
| 条件交易计划 | 考虑交易需要满足什么条件？ | 策略版本与参数、方向、入场确认、价格区间、止损与目标依据、成本假设、失效及有效期 |

三者可以在统一阅读入口展示，但必须分别表达可用性和质量。研究报告完成不代表一定有有效计划；模型失败不影响展示经验证的确定性事实，但必须明确 AI 分析不可用或降级。

## 5. 功能需求

### FR-01 任务与多轮交互

1. 用户可发起研究任务，选择已准入币种、支持的市场与周期、研究目标、策略版本和合法参数，并了解本次授权范围及预算。
2. 系统提供任务内的连续交互记录，支持用户补充信息、提出修改意见、要求补充证据、拒绝建议和取消任务。
3. 任务必须有稳定标识，刷新页面或重新进入后可以查看进度、待办和已有结果。
4. 用户输入仍须经过参数、范围、权限和预算校验。已明确给出的授权与选择不反复要求确认。
5. 相同幂等请求复用同一任务；相同请求键对应不同有效输入时拒绝冲突。不同策略版本、参数或其他影响结果的输入不得被错误合并。

### FR-02 模型驱动的研究循环

1. 支持理解目标、识别证据缺口、选择下一步、调用工具或检索、检查结果、更新分析和终止的循环。
2. LLM 实质参与情景判断、证据比较、策略适用性及候选取舍；确定性程序负责金融数值计算、权限检查和事实校验。
3. 模型可提出补充研究或向用户提问，但不能自行覆盖已选策略、突破预算或跳过强制审核。
4. 服务端必须提供最大回合、调用次数、超时和预算退出机制。证据不足或预算不足时允许停止并说明原因，不强行生成肯定结论。

### FR-03 Tool Calling 与 MCP

1. 建立服务端工具注册、输入输出契约、权限与参数约束、超时、并发限制、错误类别及调用审计。
2. 内部领域工具和 MCP 工具接受一致的治理，模型输出工具请求后，由服务端验证和执行。
3. 核心版需要实际可运行的 MCP 接入与端到端验证，至少覆盖一个已登记的只读 MCP 工具；验证可使用受控本地测试服务，不依赖付费第三方账户。
4. 运行记录能够关联调用工具、经脱敏的参数、结果引用、耗时、失败和重试；不能只展示“调用中”而没有真实调用证据。
5. 未登记工具、非法参数、越权数据及交易执行请求必须被服务端拒绝。审核同意也不能使尚未接入或禁止的工具获得执行能力。
6. 新增外部 MCP 服务、数据源或生产依赖仍需先说明方案和影响；本文件不指定具体第三方服务，也不构成无限外部接入授权。

### FR-04 RAG 与知识治理

1. 支持用户策略说明、审查后的方法文档和历史研究等知识的导入、版本管理、检索与引用。
2. 检索结果保留文档标识、版本、来源、适用范围和相关时间；不适用、停用或无权限的内容不得参与新任务。
3. 策略方法是分析知识，历史报告是历史观点，均不能替代当前行情事实。
4. 历史研究任务须按当时可得信息限制检索；无法证明历史可得性的内容不得用于声称严格的历史决策复现。
5. 无命中、命中不足、版本不匹配与检索失败应明确呈现；外部文本和用户文档不能改变系统权限。
6. 检索实现可按规模选择关键词、全文、向量或混合方式；选择哪种索引不影响必须交付可用 RAG 的要求。

### FR-05 动态上下文组织

1. 区分系统策略、用户目标、所选策略、市场事实、知识片段、会话摘要、工具观察和执行状态。
2. 根据当前步骤选择必要上下文，压缩或引用大载荷，避免无界累积聊天历史和工具全文。
3. 摘要不能改写策略版本、审批范围、关键价格、失效条件或数据限制；原始证据仍可按引用追溯。
4. 新闻、知识文本和工具输出均作为数据处理，不能升级为系统指令。
5. 本轮要求任务内上下文与交互连续性；自动学习跨会话长期记忆不作为首期默认能力。

### FR-06 Token 与预算

1. 显示可获得的输入、输出 Token、调用次数、任务耗时及预算状态；供应商未返回的用量标为未知，不能记为零。
2. 工具选择、研究分析、内容编排、上下文摘要、格式纠错和重试共同使用任务总预算，避免各阶段独立重试造成失控。
3. 单次调用前预留输出与安全收尾预算。无法安全继续时停止，或按默认审核规则申请增加预算。
4. 只有具备有效单价和用量时才展示费用估算，标明估算口径，不能冒充供应商账单或承诺绝对费用精确值。
5. 预算上限、提醒阈值和分析档位在设计阶段结合基线确定，不照搬参考方案中的候选数值。

### FR-07 分析过程可视化

1. 用户可以观察任务规划、当前分析问题、下一步目的、工具调用、检索来源、结果摘要、证据冲突和判断变化。
2. 将运行事实、模型分析摘要、行动理由和最终结论分别标识；过程解释不能作为正确性证明。
3. “思考过程”的产品口径为可审计的分析摘要与执行轨迹。模型内部完整思维链不作为可保证获取或忠实还原的交付项；供应商提供的官方推理摘要可按能力展示。
4. 不要求持久化或展示原始 `reasoning_content`。不得把原始隐藏推理、完整 Prompt、凭证或内部证据载荷直接发送到页面。
5. 流式交互优先展示安全进度和经过处理的摘要；未经验证的数值和交易计划不得作为已确认结果发布。
6. 断线恢复不能重复拼接已接收内容；终态结果和关键事件可重读。

### FR-08 专业分析报告

1. 支持市场概览、多周期结构、量价与波动、已接入衍生品背景、事件催化、支持与反证、条件情景和数据限制。
2. 未接入或不适用于当前币种的数据明确标记缺失，不为章节完整而填充推测。具体新增数据源不由章节名称自动授权。
3. 数字引用必须绑定本次可用证据或确定性计算结果，保留来源、单位、时间范围和计算版本。
4. 报告区分事实、解释和假设；周期冲突、不完整覆盖和过期数据必须影响结论呈现。
5. 以结构化内容保存并生成可读视图，支持不可变历史和修订关联；不通过全局放松旧报告校验实现新能力。

### FR-09 决策辅助与条件计划

1. LLM 可评估所选策略的适用性、比较候选、表达倾向、否决候选，并解释等待或放弃理由。
2. 计划的具体数值须来自所选策略的有效评估器和确定性计算，模型不能自由编造价格、胜率、盈亏比、数量或收益。
3. 计划必须关联本次研究、策略版本、参数、候选标识、证据、计算与模型版本；候选引用应能支持以后扩展，不能依赖固定单一数组下标。
4. 没有有效候选、数据质量不达标或策略缺少评估能力时，输出可解释的无计划状态，不改用未选策略生成计划。
5. 用户可查看完整可审阅草案；采纳动作另行记录。计划有效期、历史触发状态和当前可用性需明确区分。
6. 置信程度表示证据与判断的不确定性，未经独立校准不能当作胜率。

### FR-10 策略池

1. 支持策略录入、编辑草稿、发布不可变版本、查看、选择、停用或归档；历史报告继续关联原版本。
2. 策略包含稳定标识、说明、版本及指纹、适用市场和周期、参数 Schema、数据需求与预热要求、评估器引用和风险说明。
3. 分别标记研究可用、可生成数值计划、可回测和可模拟盘能力。文本已录入不代表算法或交易能力已实现。
4. MACD、三重过滤等为未来接入的策略示例，本轮仅交付策略池、接入契约和相应交互，不实现或宣称其信号逻辑已验证。
5. 未实现评估器的条目可以明确标识后用于方法研究；缺少可靠价格计算时不得产生数值交易计划。
6. 策略文本作为知识处理，不执行用户上传脚本或任意代码。现有技术方法文档与可计算策略须分清职责。
7. **设计建议**：初期每份计划选择一个策略，以测试评估器验证框架，并可适配现有确定性规则作为可用条目；不为满足框架验收新增未经讨论的策略算法。

### FR-11 人机交互与审核

采用用户已选择保留的默认规则：Agent 在授权范围自主研究，按决策类型触发审核；信息不明确时主动交互。完整审核规则见第 6 节。

1. 支持批准、拒绝、修改意见、要求补充证据和取消；明确每种反馈将如何影响后续步骤。
2. 强制审核由服务端规则触发，不能只依赖模型自行判断是否需要用户确认。
3. 等待时保存任务与待办，释放执行资源，不通过模型轮询等待；用户离开页面后可返回继续。
4. 用户从多个页面重复或并发提交审核时，只有合法且对应当前版本的响应可推进任务；不得重复执行或覆盖已完成的决定。
5. 审核需验证所属任务与访问权限，即使是本地单用户使用，也不能依靠猜测任务标识跨任务提交。

### FR-12 Harness、恢复与审计

1. 治理任务准入、运行策略、工具权限、预算、等待状态、超时、取消、故障恢复及审计。
2. 运行状态与不可变报告、计划版本分开。至少区分排队、运行、等待输入、等待审核、完成、降级、失败和取消；精确状态枚举在设计阶段确定。
3. 持久化可恢复的证据引用、工具结果、已验证模型结果、用户反馈与预算，不只依赖轻量 checkpoint 或请求内存。
4. 中断、恢复和重试必须有稳定标识与幂等控制。已完成调用的结果可复用，不能把恢复等同于整段付费调用自动重放。
5. 对结果未知的外部调用记录不确定状态；恢复不得默默突破原预算，必要时按审核规则请求继续授权。
6. 用户等待时长、工作执行超时和审核有效期分别管理，不让等待审核占用工作租约或被误标为执行超时。
7. 关键事件关联任务、步骤、调用、证据、策略、计划版本及审核标识；安全日志不保存原始敏感载荷。

### FR-13 可选持续监控

1. 默认关闭，单次研究发起或计划采纳不构成启用授权。
2. 启用前由用户确定监控币种、策略版本、观察条件、频率、有效期、预算和可用提醒方式，支持暂停及停止。
3. **设计建议**：以确定性触发、去重与冷却机制发现变化，再按需建立新的研究任务；避免逐次行情变化都调用 LLM。
4. 新研究沿用相同审核规则和独立快照，不能自动采纳重大修订后的计划。
5. 监控记录不回写旧报告；本轮未选定外部消息渠道，也未授权自动发送邮件或第三方消息。

## 6. 默认自主范围与审核规则

### 6.1 无须逐次审核

- 已授权范围内的行情查询、指标计算、知识检索和已登记工具调用。
- 证据比较、冲突分析、情景组织、报告及计划草拟。
- 原预算内的有限重试、上下文组织与摘要。

这些行为仍受权限、质量和预算检查约束。用户已明确选择或修改的内容，不再反复询问同一授权。

### 6.2 必须审核的决策

| 标识 | 触发条件 | 审核对象与后续行为 |
| --- | --- | --- |
| AP-01 | 采纳交易计划 | 展示完整草案及依据，复核方向、入场、止损、目标、失效及有效期；通过后记录该版本已采纳，不发单 |
| AP-02 | Agent 建议更换策略或新增策略组合 | 对比当前与建议方案及影响；未同意前不改变所选策略。组合能力未实现时不能因批准而获得该能力 |
| AP-03 | Agent 建议修改关键参数 | 展示参数前后差异及对信号和计划的影响；通过后按新参数重新评估 |
| AP-04 | 扩大研究范围 | 明确新增币种、市场类型或周期；仅能在系统已经支持的范围内扩展 |
| AP-05 | 增加任务预算 | 明确当前用量、新增上限、原因和预期后续工作；未同意前不超限调用 |
| AP-06 | 采纳重大修订后的计划 | 当新证据导致关键条件改变时生成新版本，重新复核；旧批准不自动适用 |
| AP-07 | 启用或扩大持续监控授权 | 明确监控范围、频率、期限、预算和提醒方式；单次任务批准不代替监控授权 |

AP-07 仅在可选监控已实现并可启用时适用。新增数据源或 MCP 服务的工程接入仍遵循现有变更管理，不能用运行中一次批准代替实现与审查。

### 6.3 澄清与审核的区别

策略描述不完整、目标有歧义或需要表达用户偏好时，Agent 请求澄清。补充信息须通过校验；若其同时改变授权范围、参数或预算，则按对应审核规则处理。用户已明确作出的同一项选择可形成一次有效记录，不另造重复确认。

### 6.4 审核记录与时效

1. 待审项绑定任务、动作、版本、参数及证据范围，展示原因、支持与反证、影响和有效期。
2. 没有回复保持等待或按规则过期，不默认批准。用户拒绝后不得执行该项变更；可在原授权范围继续、修改建议或结束，并明确告知状态。
3. 恢复前检查权限、策略状态、证据新鲜度和计划有效期。材料已失效时不能直接采纳；需刷新证据并重新验证，发生重大变更则生成新待审项。
4. 原版本、原反馈和新结果保留关联，不覆盖历史。用户批准不能绕过确定性校验或交易安全边界。

## 7. 数据、正确性与安全要求

1. 金额、价格、数量和费用继续使用后端 Decimal、前端十进制字符串及 decimal.js；时间统一为带时区 UTC。
2. 正式技术信号和回测只使用已收盘数据，按策略要求检查预热、连续性和时效；未收盘估算须单独标识。
3. 区分分析截至时刻、生成时刻、数据观测与可得时间、本地获取时间及修订版本；不能把公开上下文的合并参考时刻当作所有字段的真实观测时刻。
4. 动态取证须遵守本次分析的时间边界；刷新市场条件时建立新的快照或研究修订，不能暗中混合不同时间的证据。
5. 历史复核应能重读已保存结果、重放证据和确定性计算；重新调用模型不保证逐字复现原答案。
6. 工具结果、新闻和检索内容按不可信数据处理；权限由服务端确定。缺失、失败、零值、部分覆盖和历史值分别表达。
7. 研究 Agent 不生成 TradeIntent，不直接访问真实账户或下单接口，不调用模拟订单服务；新增研究能力不改变现有交易风控链路。
8. 报告、证据、计划版本和审计保持不可变或采用追加记录；现有报告与数据不因本次升级被删除、回写或伪造成功。
9. 日志、事件、前端与共享文档不包含凭证、连接串、原始思考或未经审查的内部载荷。

候选工具循环规则的含义为：允许模型在服务端授权工具、数据范围和预算内研究；所有调用经过统一验证与审计；Harness 管理运行；研究侧继续隔离账户、风控放行和执行。该描述是后续规范变更的输入，不宣称当前代码已具备此能力。

## 9. 需求取舍与采用方式

| 讨论过的交互方式 | 特点 | 本轮结论 |
| --- | --- | --- |
| 固定节点审核 | 容易预测，但对临时澄清和动态决策支持有限 | 可作为部分固定审核节点使用，不单独作为完整方案 |
| 按决策类型触发审核 | Agent 自主研究，遇到规则要求或需要用户判断时暂停 | 用户选择保留的默认方式，采用第 6 节规则 |
| 逐步人工驱动 | 每一步等待用户确认，交互负担较大 | 不作为默认；不妨碍用户主动干预 |

本轮没有把真实执行、持续监控默认启用或具体策略算法加入核心交付。RAG、MCP、上下文和预算管理则已明确为完整 Agent 的核心能力，不能无限延期后仍宣称完整目标已交付。

## 10. 验收场景与证明范围

以下为后续实现必须覆盖的验收场景，本轮仅成文，不表示这些场景已经执行或通过。

| 标识 | 场景 | 预期结果与关联需求 |
| --- | --- | --- |
| AC-01 | 正常研究中发现证据不足 | Agent 选择合法工具或检索补证，根据观察继续或结束；FR-02、FR-03、FR-04 |
| AC-02 | 受控 MCP 工具完整调用 | 经过注册、权限校验、实际调用、结果校验及轨迹记录，不仅是占位；FR-03 |
| AC-03 | 未登记工具、越权参数或证据内含指令 | 服务端拒绝越权，外部内容不能改变策略或权限；FR-03、FR-05 |
| AC-04 | RAG 有命中、无命中、旧版本或停用文档 | 正确引用适用知识，明确不足，不把历史观点当当前事实；FR-04 |
| AC-05 | 上下文超过限制 | 保留关键策略、授权与证据，通过摘要和引用控长；FR-05、FR-06 |
| AC-06 | 预算临界、重试或用量未知 | 全链路共享预算，未知如实标识，超限前停止或申请审核；FR-06、AP-05 |
| AC-07 | 同币种选择不同策略或参数并提交 | 不错误复用任务；相同幂等请求复用，冲突请求拒绝；FR-01、FR-10 |
| AC-08 | 策略条目存在但无评估器 | 可明确用于方法研究，数值计划不可用，不静默换用其他策略；FR-09、FR-10 |
| AC-09 | 采用测试评估器或适配现有规则 | 决策与计划绑定所选版本、参数和候选；无需实现新的 MACD 或三重过滤算法；FR-09、FR-10 |
| AC-10 | 草案待采纳、Agent 提议改策略或参数 | 用户能审阅完整对象，批准、拒绝或要求修改；未批准不改变所选方案；FR-11、AP-01 至 AP-03 |
| AC-11 | 扩大研究范围或已有预算不足 | 明确待审差异；原范围内继续不反复确认；AP-04、AP-05 |
| AC-12 | 等待审核时关闭页面或重启服务 | 等待和材料可恢复，未通过审批不推进，不持续模型轮询；FR-11、FR-12 |
| AC-13 | 多页面重复回复、旧版本批准或无回复 | 不重复推进，拒绝旧响应，无回复不默认批准；FR-11、FR-12、第 6.4 节 |
| AC-14 | 人工等待后行情过期或计划发生重大变化 | 原批准不沿用，重新取证校验并按需要产生新版本和审核项；AP-06、第 6.4 节 |
| AC-15 | Worker 中断、结果已保存或外部回执未知 | 恢复已有结果，付费调用不无界重放，未知状态有明确处理；FR-12 |
| AC-16 | 数据缺口、未收盘、多周期冲突或模型失败 | 展示真实质量与降级，允许无计划，不编造数值和完整覆盖；FR-08、FR-09、第 7 节 |
| AC-17 | 过程流断线重连 | 事件去重，轨迹可读，内部原始思考及敏感载荷不外泄；FR-07 |
| AC-18 | 新版本上线并读取旧报告 | 历史可读、不可变，既有研究和交易边界不被扩大；FR-08、FR-12、第 7 节 |
| AC-19 | 监控未启用或尚未实现 | 单次任务和采纳不触发监控；未实现明确不可用；FR-13 |
| AC-20 | 可选监控启用、触发、修改或停止 | 遵守范围、期限、预算、去重与审核，不自动采纳新计划；FR-13、AP-07，仅适用于该模块交付 |

验证分为软件契约与故障测试、真实模型质量评估、策略回测与模拟表现三个层面，分别报告证据，不相互替代。真实模型评估需覆盖数值与引用正确性、证据是否支持结论、反证、观望判断和策略遵循；人工复核标准及质量阈值在设计阶段建立，不能只用 Schema 通过率或模型自评宣称质量合格。

后续验收继续使用[统一质量入口](../../quality-verification.md)，按变更范围补充数据库、HTTP、浏览器及故障恢复检查。若以后涉及策略算法、回测或模拟执行，还需补无未来泄漏、手续费、滑点、部分成交、风控拒绝、熔断、幂等和对账，以及模拟盘与回测差异说明。
