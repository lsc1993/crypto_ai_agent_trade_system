# 首期确定性策略回测设计

**日期：** 2026-08-03
**状态：** 已确认，待实施计划

## 目标与范围

为现有研究工作台新增一个可审计、可重复的离线策略验证能力。用户可在前端发起一次 `BTCUSDT`、`1h` 周期的历史回测，系统读取真实且已收盘的历史 K 线，回放内置均线交叉策略，经过确定性风险校验和模拟撮合后，将报告及完整审计轨迹保存到 PostgreSQL 并在前端展示。

本期的唯一策略是版本化的内置 `sma_crossover` 基准策略；它的价值是验证数据、策略、风控、模拟执行和审计边界，而不是提供投资建议或收益承诺。首期不提供脚本策略编辑器、多币种、多周期、复杂图表工作台、模拟盘或任何真实交易能力。

## 已确认的领域约束

- 每次运行仅支持 `BTCUSDT`、`1h`、现有公开行情服务提供的真实历史 K 线。行情请求失败、返回不完整数据或出现时间缺口时，运行失败并返回明确错误；不得降级为 Mock 数据。
- 用户指定的回测区间前，会额外读取足够的历史 K 线作为均线预热数据；预热 K 线仅供计算指标，绝不生成订单或计入业绩指标。
- 在时刻 `t`，策略只可读取截至 `t` 已收盘的 K 线。由该时刻生成的订单仅能在 `t + 1` 的开盘价按模拟规则成交。最后一根 K 线不会产生可成交的策略订单。
- 策略只能生成结构化 `TradeIntent`，不能读取数据库、调用行情 HTTP 接口或调用任何交易所下单接口。首期只允许 `long` 或空仓，不支持杠杆与做空。
- 所有价格、数量、手续费、资金、权益和比率在后端使用 `Decimal`；所有市场与审计时间为带时区的 UTC 时间。HTTP 边界以十进制字符串传输金额与数量。
- 回测结束时不强制伪造成交。若仍有仓位，报告以最后一个已收盘 K 线的收盘价进行盯市，明确标识未实现盈亏；胜率和已实现交易统计仅包括已平仓交易。

## 架构与数据流

新增的模块职责如下：

| 模块 | 职责 |
| --- | --- |
| `data` | 定义 `HistoricalCandleProvider` 接口，并将现有公开行情实现适配为真实、已收盘 K 线的来源。 |
| `research/backtests` | 协调一次运行、冻结 K 线快照、回放时间轴、汇总指标并生成回测报告。不得包含真实下单实现。 |
| `strategy` | 定义 `TradeIntent`、策略元数据与 `sma_crossover`；策略只接收到当前收盘为止的市场观察值。 |
| `risk` | 使用确定性、版本化的风险配置评估意图，输出放行或带原因码的拒绝。 |
| `execution` | 纯模拟的订单状态机和撮合器；应用开盘价、滑点、手续费及可配置的部分成交比例，不接触交易所私有接口。 |
| `data/audit` | 保存运行快照、事件和运行结果，供报告与复核读取。 |

一次运行按以下顺序执行：

```text
前端请求
  -> 获取并校验已收盘真实 K 线
  -> 持久化不可变 K 线快照与运行配置
  -> 逐根回放：策略 TradeIntent -> 风控决定 -> 模拟订单/成交
  -> 计算权益、已实现与未实现指标
  -> 写入审计事件和完成状态
  -> 返回报告；前端读取详情展示
```

每个意图都有基于运行 ID、决策时点和策略版本产生的确定性幂等键。风险、执行和审计层以该键拒绝重复处理，确保一次回放不能产生重复订单或成交。

## 策略、风控与模拟执行

`sma_crossover` 的默认参数为快线 20、慢线 50：快线向上穿越慢线时请求建立多仓，向下穿越时请求平仓。参数范围在 API 层校验，且必须满足 `fast_window < slow_window`。策略版本与所有参数会写入运行记录。

默认模拟账户为：初始资金 `10000 USDT`、无杠杆、单一净持仓、最大敞口为当前权益的 `95%`、手续费 `0.1%`、不利滑点 `0.05%`、正常全额成交。撮合器的部分成交比例是显式配置项，默认 `1`；测试和后续压力验证可传入小于 `1` 的确定性比例。

初期风险规则为：禁止做空与加杠杆、禁止超过最大敞口、收盘价相对入场价亏损达到 `5%` 时生成风险平仓意图、UTC 自然日已实现亏损达到当日开盘权益的 `3%` 时禁止该日后续开仓、权益相对峰值回撤达到 `15%` 时熔断本次运行并只允许风险平仓、风险退出后冷却 3 根 K 线。基于收盘价触发的风险退出也只在下一根 K 线开盘撮合，不假设盘中价格或无延迟成交。每一次通过、拒绝、熔断与风险退出都产生审计事件。

## 持久化、API 与错误处理

本期新增一个 Alembic 迁移，独立于现有交易日志表：

| 表 | 职责 |
| --- | --- |
| `backtest_runs` | 运行身份、状态、策略及版本、用户参数、风险/执行配置、行情来源、请求区间、快照哈希、开始/结束时间、汇总指标和安全失败原因。 |
| `backtest_candles` | 与运行关联的不可变 UTC OHLCV 快照及其序号，确保详情可复算且不受外部行情服务后续变化影响。 |
| `backtest_events` | 与运行和可选 K 线序号关联的追加式决策、风险拒绝、订单、成交、风险退出、熔断及完成事件；`(run_id, sequence)` 唯一。 |

创建运行时先创建 `pending` 记录，获取并校验行情后保存快照；成功后以同一事务写入事件、摘要和 `completed` 状态。可预期的失败写入 `failed` 状态与不含凭证、连接串或原始上游响应的失败码/消息，且不写入伪造指标或半成品成交记录。

新增版本化 HTTP 端点：

- `POST /api/v1/backtests`：提交经过限定的区间和初始资金，创建并同步完成一轮首期回测。
- `GET /api/v1/backtests`：按创建时间倒序返回分页的运行摘要。
- `GET /api/v1/backtests/{run_id}`：返回配置、指标、已平仓交易摘要、未平仓盯市信息、审计事件和快照元数据。

接口使用 Pydantic 请求/响应模型；不向前端暴露 ORM 实体、原始异常、内部堆栈或任何敏感配置。数据库不可用时沿用现有安全服务错误结构。

## 前端体验

新增“策略回测”路由及导航入口。页面提供简洁表单：回测起止时间、初始资金，并显示预填的策略、手续费、滑点与风控配置。表单仅允许首期范围，提交期间禁用重复操作并展示明确的取数/校验/运行错误。

结果列表展示时间、状态、净值、收益率、最大回撤、胜率、已平仓交易数和风控拒绝数。详情页展示本次冻结的配置及行情元数据、已平仓交易表、当前未平仓盯市（如有）和时间序审计事件。首期不提供策略源代码编辑、多资产比较、交互权益曲线或从浏览器生成 Mock 回测结果。

页面必须醒目说明：回测是历史模拟，不等同于模拟盘或实盘；延迟、盘口深度、流动性、资金费率、交易所规则和实际部分成交可能使模拟盘或实盘结果不同。

## 验收与验证

所有新功能测试先行。后端应覆盖：

1. 均线预热和下一根开盘成交，证明策略无法读取未来 K 线。
2. 禁止做空、单一仓位、最大敞口、止损、日亏损限制、冷却期与熔断的放行/拒绝行为。
3. `Decimal` 手续费、滑点、全额和部分成交，以及最后持仓盯市。
4. 幂等意图、订单/成交/拒绝事件的可关联审计和快照哈希一致性。
5. PostgreSQL 迁移、原子完成/失败状态、API 校验与安全错误；数据库测试仅连接独立的 `TEST_DATABASE_URL`。

## 非目标与安全边界

- 任何真实交易、撤单、账户/余额/仓位读取、资金划转、提现、私有 API、API Key、Secret 或 Passphrase。
- 常驻或自动行情采集、任务队列、实时信号执行和模拟盘。
- AI 或浏览器自动化参与最终风控判断；风控只由确定性代码执行。
- 将历史回测报告视作投资建议、盈利承诺或可直接执行的交易指令。

## 自检

- 无 `TODO`、`TBD`、未选定范围或隐含的真实交易入口。
- 数据流、止损语义、下一根开盘成交、持久化记录、API 和前端展示一致。
- 模拟盘与回测差异已向用户说明；真实行情失败不被 Mock 掩盖。
- schema 影响明确限于新回测表和单独 Alembic 迁移；不修改 `.env`、凭证或生产连接配置。
