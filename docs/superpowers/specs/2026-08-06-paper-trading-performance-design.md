# 单账户模拟盘绩效报告设计

**日期：** 2026-08-06  
**状态：** 已确认，待实施

## 目标与范围

为现有本地、可审计的 `BTCUSDT` 模拟盘账户增加单账户绩效报告。报告只从模拟盘自己的账户状态、公开行情快照、模拟成交、账本与审计事件派生，不读取交易所私有接口、真实账户或凭证，也不提交任何真实订单。

首期只在模拟盘详情页展示当前账户的报告，不新增多账户比较页，不扩展现有手工交易日志的“复盘统计”，也不将模拟盘即时快照成交结果与历史回测结果混合计算。这样可保持三种数据源和成交语义的统计口径清晰。

## 已确认的业务边界

- 绩效只适用于单个模拟盘账户，包含活动账户与已归档账户；归档账户的报告保持只读。
- 现有手工交易日志、复盘统计和回测结果保持原有接口、页面与指标，不产生跨来源汇总或比较。
- 估值、收益、回撤和计数只使用本地已持久化的模拟盘记录。读取绩效接口不得请求新行情、触发策略、创建意图或改变账户状态。
- 所有金额、数量、价格、手续费和计算中间值使用 `Decimal`；对外仍以规范十进制字符串返回；所有时间均为带时区 UTC。
- 模拟盘仍只会经由结构化 `TradeIntent`、确定性 `RiskEngine` 与纯模拟执行层推进。绩效功能不得引入真实交易、私有交易所 API、后台定时任务或自动交易。

## 持久化与历史完整性

新增追加式 `paper_account_valuations` 表，并通过新的 Alembic `0007` 迁移创建。该表是对现有账户/仓位查询优化状态的可审计历史记录，不替代订单、成交、账本或审计事件。

| 字段 | 责任 |
| --- | --- |
| `account_id`、`sequence` | 组成主键，限定估值属于某一账户并提供稳定追加顺序。 |
| `kind` | 标识 `initial`、每次状态转换后的 `market_valuation`，或迁移前账户的 `migration_baseline`。 |
| `snapshot_id` | 初始估值为空；市场估值关联冻结的公开行情快照。 |
| `valued_at` | 与行情快照观察时间一致的 UTC 估值时间；初始点使用账户创建时间。 |
| `cash`、`position_quantity` | 估值时的账户现金与 BTC 持仓数量。 |
| `equity`、`peak_equity` | 估值时的权益与截至该点的峰值权益。 |

创建账户时，账户与空仓状态会在同一事务中追加一条初始估值。每次模拟盘状态转换时，仓储会在保存账户、仓位、行情快照、订单/成交、账本和审计事件的同一事务中，追加一条使用转换后状态的市场估值。幂等重试返回已有结果，不得创建第二条估值。归档不获取新行情，也不新增估值点。

迁移不能伪造已有账户的中间历史。对于迁移前已存在的账户，迁移只补充可核验的初始资金点和最新已存账户状态点；报告将其 `historyStatus` 标记为 `partial`。迁移后创建的账户从初始点开始完整追加，标记为 `complete`。最大回撤和权益曲线始终明确基于可用估值点计算；部分历史不能被表述为完整生命周期曲线。

## 报告计算口径

新增领域契约 `PaperPerformanceSnapshot`，按需从当前账户、当前持仓、追加式估值、账本、成交和审计事件计算。该快照不落库，也不缓存为可变业务状态。

| 指标 | 定义 |
| --- | --- |
| 当前权益 | 当前账户持久化权益。 |
| 净盈亏 | `当前权益 - 初始资金`，已包含已实现和未实现部分以及手续费影响。 |
| 总收益率 | `净盈亏 / 初始资金`。 |
| 已实现盈亏 | 所有模拟盘账本条目的 `realized_pnl` 之和。 |
| 未实现盈亏 | `当前持仓市值 - 当前剩余开仓成本`。 |
| 累计手续费 | 所有模拟成交的 `fee` 之和。 |
| 最大回撤金额/比例 | 在按估值顺序遍历的权益曲线上，使用每个历史峰值计算的最大权益回落金额及其相对峰值比例。 |
| 开仓/平仓成交计数 | 按模拟成交和对应账本动作计数；部分平仓按一次实际平仓成交计入。 |
| 盈利平仓比例 | 已实现盈亏大于零的平仓账本项，除以有盈亏的平仓账本项；没有可判定平仓时为零。 |
| 决策与风控计数 | 分别统计手动意图、策略评估、无信号、风控拒绝、风控退出、模拟订单和模拟成交。策略评估包含策略意图与策略无信号两种结果。 |

报告还返回权益曲线点（UTC 时间、现金、持仓数量、权益、净盈亏）以及历史状态、首末估值时间、点数和生成时间。初始点的行情价格为空，避免为未获取行情的创建时刻虚构价格。

## 服务与 API 契约

`PaperTradingService` 增加只读绩效查询，仓储增加读取估值记录的能力。性能汇总逻辑应位于独立的纯领域服务/模块，方便以构造的 `Decimal` 与 UTC 记录进行单元测试；它不得依赖 HTTP、ORM 或公开行情网关。

新增端点：

```text
GET /api/v1/paper-accounts/{account_id}/performance
```

响应使用 Pydantic 模型，返回账户标识、上述汇总指标、权益曲线、成交/风控计数、`historyStatus` 和 `generatedAt`。账户不存在沿用安全的 404 错误信封；存储不可用沿用 `paper_storage_unavailable` 的 503 错误信封，不暴露数据库、连接串或内部异常细节。

该端点只读取本地 PostgreSQL，不调用市场网关，因此历史账户在公开行情暂时不可用时仍可查看已保存的报告。

## 前端体验与数据契约

在 `WorkbenchApi` 增加 `getPaperPerformance(accountId)`，并在 HTTP、混合和 Mock 实现中维持显式契约。HTTP 客户端通过 Zod 校验规范十进制字符串、UTC 时间与枚举值；Mock 模式不伪造模拟收益，如模拟盘 API 不可用则保持安全的不可用状态。

`/paper-trading/:accountId` 的“账户与仓位”概览后新增“模拟盘绩效报告”区块：

- 展示收益、已/未实现盈亏、手续费、最大回撤与平仓统计 KPI；
- 使用只读权益曲线和其文本数据表呈现估值历史，显示层不改变或保存原始十进制数据；
- 显示策略、无信号、风控拒绝/退出、订单和成交计数；
- `historyStatus=partial` 时明确提示图表只覆盖迁移基线之后的可用记录；
- 绩效加载或失败只影响该区块，现有账户、持仓、审计和操作区继续可用。

手动开仓、平仓、策略评估或归档成功后，会同时失效并重新读取账户详情和对应绩效查询。页面不新增下单、风险配置或跨账户操作入口。

## 测试与验证

测试先行，至少覆盖：

1. 纯绩效聚合对无成交、开仓盯市、平仓已实现盈亏、手续费、部分平仓、正/负回撤和零分母的 `Decimal` 计算。
2. 估值创建、每次状态转换追加、同一幂等键不重复写入、归档不生成虚构估值，以及迁移前账户的部分历史基线。
3. API 的成功响应、未知账户 404、存储不可用 503、十进制/UTC 序列化与只读行为。
4. 前端领域 schema、HTTP/混合 API 契约、加载/失败/空数据/部分历史提示，以及操作后绩效刷新。
5. 既有模拟盘、策略、风控、订单、成交、账本和审计测试继续通过，证明绩效读取不会改变交易状态或绕过风险边界。

## 非目标与安全边界

- 多账户排行榜、跨账户对比、账户聚合、回测对比或与手工交易日志的混合统计。
- 向迁移前账户回填或猜测未被可靠保存的中间行情和估值历史。
- 实盘、交易所私有端点、API Key、账户余额读取、下单、撤单、资金划转、提现或任何自动执行。
- 后台采集、定时策略评估、任务队列、WebSocket 订单触发或收益承诺。

## 自检

- 设计只追加可审计的本地估值记录，未引入真实交易路径或凭证。
- 现有模拟盘即时快照成交、回测下一根开盘成交、手工交易日志三类数据保持独立口径。
- 历史完整性显式建模，迁移不伪造数据。
- 计算、API、前端状态与测试均以 `Decimal`、UTC、确定性风险和安全错误边界为前提。
