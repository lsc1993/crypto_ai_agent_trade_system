# 手动触发的可审计模拟盘设计

**日期：** 2026-08-04
**状态：** 已实施并验证

## 目标与范围

在现有确定性回测能力之上，新增一个无需常驻进程、由用户手动触发的模拟盘工作流。它让用户在本地创建一个持久化的 `BTCUSDT` 模拟账户，通过手动操作或现有 `sma_crossover` 策略产生结构化意图，并以一次固定的公开行情快照进行确定性风险校验和即时模拟成交。

该能力用于验证研究纪律、风控语义和审计链路，不构成投资建议、收益承诺、模拟盘与实盘等价性承诺，也不能产生任何真实订单。首期不引入后台轮询、队列、WebSocket、交易所私有接口、账户读取或凭证。

## 已确认的业务边界

- 仅支持 `BTCUSDT`，单一活动模拟账户和单一净持仓；首期只允许空仓或多仓，不支持做空、杠杆、多资产或组合风控。
- 手动意图和策略意图共用同一账户、现金、持仓、风控配置、成交配置和审计链路。手动操作影响策略下一次评估时看到的真实模拟持仓。
- 首次使用时，用户显式创建模拟账户；初始资金为以十进制字符串提交的 USDT 金额，前端默认值为 `10000`。系统不自动创建账户或隐式扣减资金。
- 同一时刻只有一个活动账户。用户只能在持仓已平的情况下归档账户，再创建新账户；归档保存完整历史并将账户转为只读，绝不删除原有订单、成交、账本、行情快照或审计事件。
- 手动操作只提供 `open_long` 与 `close_long`。开多使用确定性风控允许的最大仓位，平多关闭当前持仓；首期不提供金额、限价、挂单、部分平仓或手工绕过风控的入口。
- 用户点击“策略评估”时，服务端读取最新已收盘的 `BTCUSDT` 1h K 线，复用已版本化的 `sma_crossover` 策略。无均线交叉时仅记录无信号审计事件，不生成订单或成交。
- 每一次手动意图或策略评估仅获取一次固定公开行情快照。通过风控的意图按快照价格、固定不利滑点与手续费即时模拟为市价成交；不等待下一根 K 线，也没有后台自动成交。
- 历史回测仍保持“收盘决策、下一根开盘成交”的语义。模拟盘即时快照成交与回测结果不应直接比较；延迟、盘口深度、流动性、资金费率、交易所规则和实际部分成交均可能造成差异。

## 架构与数据流

新增 `paper_trading` 领域模块，协调账户会话、意图来源、公开市场快照、风控、模拟执行和审计。它依赖现有公开 Binance USDⓈ-M 行情边界、策略契约、确定性风险规则和纯模拟撮合器；业务模块不得直接调用交易所私有 API 或真实下单适配器。

```text
手动开多/平多 或 手动触发策略评估
  -> 结构化 TradeIntent（标明 manual / strategy 来源）
  -> 一次公开行情快照并冻结证据
  -> 确定性 Risk Engine 通过或拒绝
  -> 模拟市价订单、滑点、手续费与即时成交
  -> 同一事务更新账户/持仓并追加账本、订单、成交、审计事件
  -> 返回最新账户状态与本次操作结果
```

### 意图、风控与执行

手动请求先在 API 边界校验为 `open_long` 或 `close_long`，再转换为结构化 `TradeIntent`。策略也只能产生同一契约的意图。意图必须记录账户 ID、标的、动作、来源、策略标识/版本（适用时）、决策时间与幂等键；它不包含交易所凭证、真实订单 ID 或真实账户信息。

风险层是唯一能放行意图的组件。它基于活动账户的现金、持仓、权益和固定配置执行单一仓位、最大敞口、止损、日亏损限制、熔断和冷却期校验。拒绝理由使用稳定原因码；LLM、浏览器或前端传入内容均不能放行或修改风控结果。

通过的意图由纯模拟执行层以冻结快照价格应用不利滑点、手续费和现有确定性成交语义。执行层不得访问网络或数据库；所有金额、数量、价格、手续费、现金与权益使用 `Decimal`，所有时间使用带时区的 UTC。

### 幂等与并发

手动请求携带由客户端生成的请求 ID，并以账户与请求 ID 形成幂等键。策略评估以账户、策略版本和最新已收盘 K 线时间形成确定性幂等键。相同幂等键的重试返回既有结果，不得重复冻结行情、扣减现金或生成成交。

更新活动账户时，仓储以同一数据库事务锁定账户记录，再读取当前持仓和余额、保存快照、写入风控决定、订单/成交、账本和审计事件。这样并发点击不能产生超过最大敞口的持仓或重复成交。

## 持久化与不可变审计

模拟盘使用独立 schema，不复用手工交易日志表，确保人工记录和系统模拟结果保持可区分。

| 表 | 责任 |
| --- | --- |
| `paper_accounts` | 账户会话、初始资金、当前现金/权益、固定风险和执行配置、状态与 UTC 创建/归档时间。 |
| `paper_positions` | 活动账户的当前 BTCUSDT 持仓数量、平均开仓价和盯市状态；只表示当前状态。 |
| `paper_market_snapshots` | 每次操作使用的公开行情、来源、抓取时间和规范化快照哈希。 |
| `paper_orders` | 从已放行意图派生的模拟订单及其状态、来源和幂等键。 |
| `paper_fills` | 模拟成交价格、数量、滑点、手续费与成交时间。 |
| `paper_ledger_entries` | 现金、持仓数量、已实现盈亏和手续费的追加式变更账本。 |
| `paper_audit_events` | 意图、无信号、快照失败、风控结果、订单、成交、归档和安全失败的顺序事件。 |

订单、成交、行情快照、账本和审计事件追加后不可修改或删除；数据库迁移须为这些记录建立不可变性保护。账户仅能由 `active` 转为 `archived`，归档后所有写操作被拒绝。当前账户现金与持仓是查询优化状态，必须可由不可变账本、成交和事件进行复核。

行情不可用、返回不完整或已归档账户被操作时，服务安全失败且不伪造成交。若数据库本身不可用，沿用现有错误信封，不能承诺审计已保存。

## HTTP 契约

所有接口位于 `/api/v1`，使用 Pydantic 请求/响应模型。金额与数量以规范十进制字符串传输，时间使用 UTC RFC3339 字符串；不暴露 ORM 实体、数据库异常、连接串、上游原始响应或敏感配置。

- `POST /api/v1/paper-accounts`：以初始资金创建账户；已有活动账户时安全拒绝。
- `GET /api/v1/paper-accounts`：按创建时间返回账户摘要分页列表。
- `GET /api/v1/paper-accounts/{account_id}`：返回账户配置、现金、权益、当前持仓、订单/成交摘要、账本、快照元数据与审计事件。
- `POST /api/v1/paper-accounts/{account_id}/manual-intents`：以客户端请求 ID 提交手动开多或平多意图。
- `POST /api/v1/paper-accounts/{account_id}/strategy-evaluations`：以策略/最新收盘 K 线的幂等键触发一次 SMA 评估。
- `POST /api/v1/paper-accounts/{account_id}/archive`：仅允许空仓账户归档，不删除数据。

`mock` 模式不生成虚构账户、订单或收益；模拟盘页面明确提示它需要本地 API 与 PostgreSQL。`api` 与 `market-api` 模式委托真实 HTTP 接口，并在失败时显示后端提供的安全错误码和消息。

## 前端体验

新增“模拟盘”导航入口、账户列表和账户详情页。无活动账户时，页面展示初始资金表单及醒目的“仅模拟、不连接真实账户、不产生真实订单”说明。

活动账户详情展示现金、权益、已实现/未实现盈亏、最大回撤、当前 BTCUSDT 持仓、行情来源与抓取时间、固定手续费/滑点/风控参数。手动开多、平多和策略评估各自有明确按钮；请求期间禁用重复提交，并呈现成功、无信号、风险拒绝或行情不可用状态。

订单、成交、账本和审计事件按时间展示，能追溯到意图来源、幂等键、风控决定和对应行情快照。归档操作要求二次确认；历史账户页面只读，用户可在归档后创建新账户。

## 验收与验证

测试先行，至少覆盖：

1. 手动与策略操作都转换为 `TradeIntent`，且任何路径都不能绕过确定性风险引擎。
2. 账户创建、单一活动账户、归档只读和新账户创建；归档不会删除历史。
3. `Decimal` 现金/权益计算、手续费、滑点、持仓盯市、止损、日亏损、熔断、冷却期、现金不足和最大敞口。
4. 手动/策略幂等键、并发请求和数据库事务语义；不能产生重复成交或超额仓位。
5. 行情快照冻结、账本可复核、订单/成交/审计事件不可变，以及迁移隔离测试仅使用 `TEST_DATABASE_URL` 的临时 schema。
6. API 请求校验和安全错误；公开行情失败不回退 Mock 或伪造成交。
7. 前端创建账户、手动开平仓、策略无信号、拒绝/失败显示、重复提交禁用、归档确认与只读历史账户。
8. 公开 Binance 行情下的一次手工模拟盘检查，并记录它与历史回测成交语义的差异。

## 非目标与安全边界

- 自动、定时或后台策略评估；常驻采集、任务队列、WebSocket 订单触发或自动成交。
- 限价单、挂单、部分平仓、做空、杠杆、多资产、策略参数优化、策略比较和组合风控。
- 真实交易、撤单、账户/余额/持仓读取、资金划转、提现、交易所私有 API、API Key、Secret、Passphrase 或私钥。
- 将模拟盘结果表述为投资建议、盈利承诺、可执行交易指令或模拟盘与实盘等价性证明。

## 自检

- 无未决范围、`TODO` 或 `TBD`；共享账户、即时快照成交、归档语义与无后台约束一致。
- 所有交易请求均经过结构化意图、确定性风控和纯模拟执行；不存在真实下单路径。
- 存储模型区分人工交易日志与模拟盘，并支持历史不可变审计和当前状态复核。
- 数据库、时间、数值、错误边界、前端模式和测试策略均符合现有工程与安全约束。
