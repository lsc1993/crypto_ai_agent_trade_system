# 技术研究交易计划书与两阶段模型生成

日期：2026-10-09。状态：用户已确认书面设计，待实施；确认不代表功能已实现。

## 目标与已确认方向

用户希望独立技术研究输出围绕入场、止损、目标和等待条件展开的交易计划书，解释选用的 Skill、支持证据、冲突证据和失效条件。保留综合研究报告；不新增账户访问、TradeIntent、风控放行或执行入口。用户已同意思考分析、确定性校验、非思考编排的两阶段方向。

成功标准是报告能解释“为何考虑这个计划、为何现在执行条件成立或尚不成立、什么情况取消判断”，而不是增加模板篇幅。没有合格候选时输出具体等待计划，不强行创造入场价格。

## 当前实现与差距

- `agent/technical/engine.py` 已从日线、4h、1h 已收盘行情计算均线、量比、ATR、区间、结构位及成本后盈亏比。当前最多生成一个多周期同向的突破候选。
- `agent/technical/model.py` 当前只发送定性投影，关闭思考，额度 2400；三类短文本不足以解释交易计划。领域及模型校验全面拒绝数值和部分交易术语。
- `POST /technical-reports` 同步返回报告；技术模型复用请求超时配置，当前配置上限 60 秒。前端等待整个生成请求完成。
- 报告及冻结证据以 JSONB 保存；报告保存事务中的数据库触发器写 Harness 终态。既有报告不可变。
- 工作区包含上一轮技术模型修复及其他任务改动。本次只纳入技术研究相关差异，保留其他改动。

## 方案选择

选择两阶段模型与持久化后台任务。单调用增加额度仍会让思考和正文共享额度；单纯放宽正文校验不能解决依据不足。两阶段增加延迟和调用成本，但分析与编排可独立限制、验证和降级。

本期继续使用现有确定性突破候选规则，不降低盈亏比或数据质量门槛。主计划最多一个；备选情景可以是取消、转为等待或重新研究，只有存在程序验证的候选才能包含完整价格计划。增加回踩、逆势反转等独立候选算法属于后续工作。

## 固定数据流与证据

公开行情采集并冻结 → 确定性指标和候选计划 → 思考分析 → 分析校验 → 非思考编排 → 正文校验与确定性数值渲染 → 不可变保存。

模型获得完整、有限的冻结指标、当前摘要价格、最近已收盘价格、截止时间、候选计划、拒绝理由和本次选定方法。所有数值使用公开契约的十进制字符串。输入不包含私有账户、凭证、任意文件、新闻或工具定义。重试使用同一冻结证据，不重新采集。

建立只读事实引用表：稳定字段路径作为 factRef，候选索引作为 planRef，方法 ID/version 作为 methodRef，所有引用同时绑定本次 evidenceId。数值与字段语义共同绑定；仅数值存在于某处不能证明引用正确。模型不得修改、重算或新增价格。

## 第一阶段：开启思考的结构化分析

输出 `TechnicalDecisionSummary`：

- 推荐立场：条件多、条件空或等待；选中的候选引用可为空。
- 市场结构：周期一致与冲突、量价和形态的支持与反证。
- 方法应用：本次选定方法、满足的条件、未满足的条件及适用限制。
- 主情景：入场确认、止损依据、目标依据、取消条件及有效期解释。
- 备选情景：何种变化导致主情景失效，以及下一次需复核的事实。
- 等待清单：缺少的确认条件及观察对象；无候选时必须与程序拒绝理由一致。

每项解释使用有界中文文本、证据和事实/方法引用。决策只能引用存在且有效的候选；模型可拒绝已有候选并转为等待。没有候选不能推荐条件多空计划。方法说明不能伪装成市场证据。

原始 `reasoning_content` 不展示、不保存、不加入纠正请求或后续模型输入。仅保存经过校验的最终分析摘要、版本和安全诊断。

## 第二阶段：关闭思考的报告编排

输入已校验摘要、相同事实引用表和候选计划；输出市场判断、主计划解释、备选情景、等待条件、方法应用和风险。各节有独立长度上限，取消当前 40–80 字指导；优先完整解释，不以字数充当质量验收。

数字通过结构化 factRef/planRef 或受控占位符引用，由程序渲染为精确数值与单位。允许“入场、止损、目标、条件做多/做空”等研究术语；继续拒绝账户金额、仓位、杠杆、下单指令、收益承诺与未经支持的数字。禁止任意自由数字，通过引用渲染避免错误周期、价格和指标互换。普通中文数字词不按字符逐字禁止。

程序检查正文是否与第一阶段选择和等待立场一致，候选状态与截止时间是否被正确呈现。历史触发不表述为实时可执行。编排失败可用已校验摘要和确定性计划生成明确标识的规则编排结果，不冒充模型成功。

## 输出版本与降级

新增 `technical-v2` 契约，保留 `technical-v1` 的校验与读取路径。v2 包含决策摘要、计划书分节、生成来源/质量及分阶段诊断。现有事实与计划保留。前后端按 version 解码，不改写旧 JSON 或旧报告。

模型完整成功、分析成功但规则编排、模型分析不可用、行情不足分别标识。分析失败仍保存本次确定性事实、候选/拒绝理由和等待信息，不伪造分析。错误码区分阶段、额度耗尽、空正文、超时、上游错误、引用/契约错误。安全诊断只包含阶段、次数、finish_reason、token 计数、耗时与白名单错误类别；不记录原始正文或 Prompt。

## 额度、重试与超时

为技术模型新增独立可校验的设置，不改变综合报告配置，不编辑 .env。初始建议：分析 thinking enabled、reasoning_effort high、总 completion 上限 32768；正文 thinking disabled、上限 8192。这是需评估的起始限制，不保证所有请求能完成。

分析最多两次、编排最多两次，总任务执行截止 600 秒；分析单次最长 180 秒，编排单次最长 90 秒，行情和存储也受总截止限制。仅在剩余截止预算足够时重试。

- finish_reason=length 或空正文：作为单独失败类别；分析可在第二次保持 thinking enabled 并降低到 low，正文用同等额度重试。不得无限加大额度。
- 合约/引用失败：用白名单字段路径和错误类别纠正，不回传原始错误文本。
- 临时上游故障可进行一次有界重试；认证和参数错误不重试。限流遵守剩余预算与受限 Retry-After。
- 达到阶段/总截止及时结束模型调用并保存降级；数据库不可用导致任务失败，不声称保存成功。

记录请求的模型、思考等级、额度和 Prompt/契约版本；不储存凭证。使用响应尺寸上限，但按新的思考额度设置合理上限，避免沿用 64KB 误拒有效响应。

## 后台任务、接口与持久化影响

新增持久化技术研究任务表和一条前向 Alembic 迁移；不修改历史迁移、不清理业务数据。字段包含任务 ID、币种、生命周期、阶段、UTC 时间、运行关联、最终报告 ID、安全失败码以及租约信息。冻结报告继续存入现有表；摘要随 v2 报告 JSON 保存，无需更新旧记录。

新增 `POST /technical-reports/runs` 返回 202 和任务资源；`GET /technical-reports/runs/{run_id}` 查询状态。保留原有同步 POST 契约以兼容现有调用方；新前端使用后台接口。静态 runs 路由先于 report_id 路由注册。

状态：queued、running、completed、degraded、failed；阶段：queued、collecting、analyzing、validating、composing、saving、finished。状态只允许规定的前向转换。提交时和执行时均核验研究币种准入。客户端请求标识提供幂等性；同标识不同币种拒绝。同币种活跃任务复用，并限制队列容量（初始 20）和执行并发（初始 1），避免重复点击产生多次付费调用。

API lifespan 中增加专用固定研究 worker，不扩展币种同步 worker 或 Harness 的工具权限。通过数据库原子领取及租约防止重复领取；租约有心跳，过期运行标记 interrupted，不自动重放可能已付费的模型调用。未开始的 queued 任务可继续处理；服务关闭停止领取并有界结束运行。多实例不能依靠单进程锁。

worker 在运行时进入现有 Harness 策略与审计，任务关联其运行 ID。报告保存后的终态与任务映射须可恢复：若报告已提交但任务更新中断，凭唯一运行关联找回报告，不重新调用模型。存储失败保持失败状态；不写虚假的报告 ID。

前端轮询任务状态并显示当前阶段；刷新页面或临时查询失败后可继续查看同一任务。终态后停止轮询，导航到报告；切换币种不能让迟到结果跳转到错误币种。无需估计百分比或承诺完成时间。

## 展示

v2 首屏呈现当前立场、数据截止、主要依据与等待条件，其次展示主计划的入场确认、结构止损、目标、成本后盈亏比、失效条件与期限，再展示备选情景、方法应用和风险。详细方法指纹和报告审计放在后部。无候选时突出具体等待条件及缺失依据，不展示虚构价格卡。

v1 沿用旧展示。Mock、HTTP、Hybrid 均提供新任务与 v2 解码；Mock 明确为演示。任何阶段降级、数据不足和旧快照都需明确呈现。

## 验证与验收

先写失败测试再实现。固定行情与模型替身验证：完整成功、无候选等待、多周期冲突、分析拒绝候选、伪造引用、数值/单位错配、空正文、额度耗尽、工具调用、超时、有限重试、阶段降级和安全日志。现有闭合 K 线/无未来数据、价格几何和成本测试继续通过。

专用测试 PostgreSQL 验证迁移、队列幂等/并发领取/容量、租约中断、保存恢复、冻结证据及 Harness 终态事务，验证 v1/v2 混合历史读取。前端覆盖阶段轮询、终态停止、刷新恢复、切换币种、降级、计划/等待卡片和三种适配器；关键路径补 Playwright。

后端执行 Ruff、Pyright、pytest；前端执行 lint、typecheck、Vitest、build，说明目录、结果和未验证项。同步维护技术报告、AI 维护、运行边界、部署说明和项目状态；变更运行边界时执行安全文档测试。

替身测试只证明流程和边界；真实思考质量仍需固定样本评估。真实调用应单独说明调用数量和预期成本影响，经用户同意后使用现有配置；不得读取或输出密钥。推送、迁移和部署按用户后续指示执行。
