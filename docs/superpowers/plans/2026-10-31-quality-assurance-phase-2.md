# 质量验证第二阶段设计与实施计划

## 目标与工程选择

在现有质量入口上补 HTTP/数据库浏览器闭环、AST 架构检查、技术 v2 与研究服务降级评估、安全失败诊断及归档；经审查提交功能分支并验证远端 CI。用户已要求按这些建议执行，不扩展交易权限、不改业务数据库/schema、不使用真实模型或公开网络样本。采用现有 pytest/Playwright 与标准库，不新增依赖。

HTTP 验收使用专用测试库的随机 schema，固定服务装配与合成样本，浏览器必须走实际 HTTP 后端并验证刷新读取；不以 Mock API 或前端拦截替代持久化。AST 检查聚焦研究、Harness、策略风控交易隔离，解析绝对/相对导入及明确动态导入；不宣称覆盖任意运行期代码执行。评估直接调用生产服务/模型验证链，样本及测试 helper 分离，结果不代表真实模型研究质量。

诊断仅归档受校验的测试文件/函数标识、结果和计数，不保存原始异常、参数值或外部文本。CI 保存评估指纹和安全报告，失败不发布或部署。远端写入遵守具体仓库/分支授权，权限或审批不足时明确报告，不绕过。
