# 隔离 Compose 运行与恢复验收

> **For agentic workers:** Use superpowers:executing-plans to execute and record evidence. No remote CI, push, merge, deployment to business environments, or real model requests.

**Goal:** 对当前 Dockerfile、入口迁移、完整应用 lifespan、Nginx 与 PostgreSQL 做本地运行验收。

**Architecture:** 从生产 Compose 渲染生成临时隔离配置，独立项目/镜像名/端口/卷；API 与 PostgreSQL 仅连接 internal 网络、空模型密钥。前端另连接独立入口桥接网，以支持 Docker Desktop 的本机端口发布。使用合成交易日志验证持久化，不把外部源不可用当作成功同步。

**Tech Stack:** Docker Compose、PostgreSQL 17、现有后端与前端生产镜像、Playwright。

## 约束

- 不读取或修改用户 `.env`，不复用固定业务卷或业务容器。
- 所有构建、运行、备份与恢复只针对本次独立资源，备份仅含合成数据。
- `down` 保留卷用于重建证明；最终回收前核对项目和本次资源标签，禁止全局 prune。
- 不增加生产依赖、数据库迁移或更改交易能力。除发现真实缺陷外，不新增持久化验收基础设施。
